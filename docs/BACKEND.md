# Backend

Quantum Foundry is an independent personal project and is not an official Google product.

## Structure

- `api/v1/routes`: FastAPI route modules.
- `services`: business logic and export generation.
- `schemas`: Pydantic request/response contracts.
- `models`: SQLAlchemy models.
- `db`: database session setup.
- `seeds`: deterministic seed data.

## Routers

Implemented routers cover health, projects, sessions, use cases, assessments, circuits, architectures, artifacts, jobs, usage, and guide.

## Service Lifecycles

- Circuit run: request -> foundry-core template/simulation -> `CircuitRun` record.
- Assessment: request -> QALS 3.0 deterministic rules -> `Assessment` and `AlgorithmContract` response/record.
- Serious Build: eligible Algorithm Contract -> `ExperimentBundle`; only a valid, complete compute contract queues an async simulation job. The worker revalidates assessment, contract, bundle, baseline, and PQC gates before execution.
- Architecture: assessment/contract context -> contract-specific mapper -> `ArchitectureRecord` with Result Trust.
- Guide: request -> deterministic context bundle -> answer, sources, next actions.
- Artifacts: request/job -> generated bytes plus contract Result Trust context -> storage adapter -> `Artifact` record.

The tutorial circuit endpoint remains assessment-free and always returns educational trust labels. It
does not create a serious Experiment Bundle. Contract-mode eligibility is enforced in the backend
service and cannot be bypassed by a frontend-only action.

## Testing Strategy

Backend tests use FastAPI TestClient, fake async sessions where useful, and foundry-core unit tests for quantum logic.
